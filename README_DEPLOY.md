# gomusin.cloud 실제 배포

## Render 배포
1. 이 폴더를 GitHub 저장소에 업로드합니다.
2. Render에서 New → Blueprint를 선택하고 GitHub 저장소를 연결합니다.
3. ADMIN_PASSWORD 환경변수에 강력한 초기 관리자 비밀번호를 입력합니다.
4. 배포가 끝나면 Render의 Custom Domain에 gomusin.cloud를 추가합니다.
5. Render가 보여주는 DNS 레코드를 카페24 DNS 관리 화면에 그대로 입력합니다.
6. HTTPS가 활성화되면 https://gomusin.cloud로 접속합니다.

중요: 고객 개인정보를 저장하므로 운영 전 개인정보 처리방침, 직원 권한, 백업, 보안을 검토하세요.

## 직원 이메일 인증

직원 가입은 이메일 인증 → 승인대기 → 관리자의 소속 지점 지정/승인 순서입니다.
연락처는 보관하되 신규 가입 인증/승인 안내에 SMS를 사용하지 않습니다.
기존 전화번호 기반 아이디 찾기/비밀번호 재설정은 별도 기능으로 유지합니다.

운영 시작 전 Resend에서 발신 도메인을 검증하고 발송 전용 API 키를 발급합니다.
Render 환경변수 `RESEND_API_KEY`, `EMAIL_FROM`(검증된 도메인의 주소만)을 설정합니다.
API 키는 Git이나 채팅에 넣지 않습니다. HTTPS API를 사용하므로 SMTP 포트가 필요 없습니다.
계정 생성/도메인 검증/요금 동의는 소유자가 완료해야 합니다.

설정이 없으면 발송·가입 버튼을 비활성화하며 인증을 우회하지 않습니다.
발송 실패, 10분 만료, 1분 재발송 제한, 주소당 시간당 5회/IP당 20회 제한,
5회 입력 실패, 다른 회사/다른 이메일, 재사용된 인증번호는 차단합니다.
이메일 발송 실패 시에도 요청 횟수를 보존합니다. 인증번호는 원문 저장하지 않습니다.
기존 테이블에는 nullable 이메일 컬럼만 추가하고 별도 인증 테이블을 생성합니다.
배포 후 실제 직원 이메일로 수신을 확인한 뒤 가입/관리자 승인/소속 지점 접근을 확인하세요.
