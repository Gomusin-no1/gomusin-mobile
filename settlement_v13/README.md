# 정산 대사 프로그램 (판매일보 vs 거래처 정산서)

뽀로로모바일(본점·2호점·3호점) 판매일보와 거래처 정산서를 건별로 맞춰서,
**일치 / 초과(정산서가 더 줌) / 부족(정산서가 덜 줌)** 을 색으로 구분한 엑셀과 JSON 결과를 만듭니다.
2026년 8~9월 실제 데이터로 검증한 로직을 그대로 담았습니다.

현재 지원 거래처 (판매일보 '청약점' 값 기준):

| 코드 | 거래처 | 청약점 | 정산서 형태 |
| --- | --- | --- | --- |
| `gyeonggi` | 경기서부모바일 | 경기 | .xlsx 1개 |
| `juan` | KT ㈜주안정보통신 | 주안 | 계정(매장 코드)마다 .xls 1개 |
| `naeway` | 내외정보통신 | 내외 | .xlsx 1개 |

나머지 거래처(신도, 프리스비, 모빙 등)는 정산서 양식을 받는 대로 `settlement/vendors/` 에 파일 하나씩 추가하면 됩니다(아래 "거래처 추가").

---

## 1. 설치

Python 3.10 이상.

```
pip install -r requirements.txt
```

KT 주안 정산서처럼 **.xls(구형 엑셀)** 파일은 `xlrd` 로 읽고, xlrd 가 없으면 LibreOffice(`soffice`)로 변환해서 읽습니다.
(LibreOffice 변환 경로는 실제 9월 파일로 검증했고, xlrd 경로는 같은 결과가 나오는지 처음 한 번 확인해 주세요.)

## 2. 실행

```
python run.py --year 2026 --month 9 \
  --sales 본점=판매일보/2026년_본점_판매일보.xlsx \
  --sales 2호점=판매일보/2026년_2호점_판매일보.xlsx \
  --sales 3호점=판매일보/2026년_3호점_판매일보.xlsx \
  --vendor gyeonggi 정산서/26년09월_경기서부모바일_정산서.xlsx \
  --vendor juan 정산서/주안_2609_2호.xls 정산서/주안_2609_3호.xls \
  --out 결과
```

- `--sales` : 매장마다 한 번씩. 판매일보 파일 안에서 `09월` 또는 `9월` 시트를 자동으로 찾습니다.
- `--vendor` : `거래처코드 파일1 [파일2 ...]`. 주안처럼 계정별로 파일이 여러 개면 한 번에 모두 넣습니다.
- 결과: `결과/9월_경기서부모바일_대사.xlsx` + 같은 이름의 `.json`

코드에서 바로 쓰려면:

```python
from settlement.engine import reconcile
from settlement.report import write_excel

res = reconcile("gyeonggi", 2026, 9,
                {"본점": "...xlsx", "2호점": "...xlsx", "3호점": "...xlsx"},
                ["경기_09.xlsx"])
res["summary"]           # 건수·금액 요약
res["items"]             # 매칭된 건별 비교 결과 (화면 표에 그대로 쓰면 됨)
res["unmatched_vendor"]  # 정산서에만 있는 줄 + 퀵비 등 매장단위 항목
res["unmatched_sales"]   # 판매일보에만 있는 줄 (+ 추정 사유)
write_excel(res, "결과.xlsx")
```

## 3. 결과 읽는 법

엑셀 시트 구성:

1. **비교결과**: 빨간색(부족) → 초록색(초과) → 노란색(일치) 순서로 정렬. 금액(판매일보 / 정산서 / 차이)과 항목 합계가 보입니다.
   **고객명을 누르면 그 고객 판매 건만 있는 시트**(맨 뒤쪽 `001_이름` 탭)로 이동합니다.
2. **고객별 시트(001_이름 …)**: 그 고객 한 건만 보여줍니다. 판매일보 항목(메모 줄)과 정산서 항목을 짝지어
   **맞는 항목은 초록 글씨, 틀린 항목은 빨강 글씨**로 표시하고, 아래에 예상 원인과 판매일보 메모가 나옵니다.
   `← 목록으로`(목록의 그 줄로 돌아가기), `◀ 이전 고객 / 다음 고객 ▶` 링크가 있고, 탭 색은 빨강=부족·초록=초과·노랑=일치입니다.
3. **미매칭_정산서**: 판매일보에서 못 찾은 정산서 줄, 퀵비·유심 구매·환수 같은 매장단위 항목
4. **미매칭_판매일보**: 정산서에 없는 판매 건과 추정 사유(월말 개통이면 다음 달 반영 가능 등)
5. **안내**: 계산 규칙 설명

JSON 의 `items` 한 건 주요 필드:

| 필드 | 뜻 |
| --- | --- |
| `status` | `match` 일치 / `more` 정산서가 더 줌 / `less` 정산서가 덜 줌 |
| `sales_cmp` / `vendor_cmp` / `diff` | 판매일보 비교금액 / 정산서 비교금액 / 차이(정산서−판매일보) |
| `rebate_sale` / `rebate_vendor` / `rebate_diff` | 리베이트만 따로 비교 (유선 등 분리 불가하면 `null`) |
| `other_sale` / `other_vendor` / `other_diff` | 리베이트 외 조정(구두·차감 ↔ 정산서 정책 항목) |
| `vendor_other_note`, `sale_other_note` | 항목별 금액을 풀어 쓴 문장 |
| `excluded_sale`, `excluded_vendor` | 차액 계산에서 뺀 항목(참고용) |
| `flag` | 2차 매칭 사유 (없으면 `null`) |
| `cause_text` | 예상 원인 한 줄 요약 (일치면 빈 값) |
| `causes[]` | 예상 원인 목록 `{category, amount, confident, text}` — category: 정책 단가(리베이트) / 부가서비스 / 개통 조건 / 정책 추가금 / 판매일보 메모 / 매칭 |
| `checks[]` | 큰 틀 점검표 `{name, status(ok/warn/bad), text}` — 정책 단가, 부가서비스, 개통 조건, 정책 추가금 |
| `memo_match` | 판매일보 메모 ↔ 정산서 항목 대조 `{pairs, memo_only, vendor_only}` (메모 합계가 구두−차감과 같을 때만, 아니면 `null`) |
| `sale_memo` | 판매일보 AE열 메모(구두내용/부가추가/차감내역) 원문 |
| `vendor_items[]` | 정산서 상세 항목 `{label, amount(매장 기준), category}` |
| `store`, `seller`, `date`, `name`, `phone`, `device` | 매장·판매자·개통일·고객·번호·기종 (판매일보 기준) |

## 5. 거래처 추가

1. `settlement/vendors/새거래처.py` 를 만들고 `base.Vendor` 를 상속합니다. 기존 3개 파일이 예시입니다.
   - `load()` : 정산서에서 건별 행과 매장단위 항목을 읽기 (열은 **항목명으로 찾기** — 거래처가 달마다 열 위치를 바꿉니다)
   - `strict_key()` : 번호·이름·날짜로 1차 매칭
   - `compare()` : 정산서 쪽 비교금액·리베이트·제외 항목 계산
2. `settlement/vendors/__init__.py` 의 `VENDORS` 에 한 줄 추가
3. `RULES.md`(정산 규칙 명세) 에 그 거래처 규칙을 적고, 실제 한 달 치로 돌려서 리베이트가 대부분 일치하는지 확인합니다.
   (지금까지 3개 거래처 모두 판매일보 R/B 와 정산서 리베이트 열이 원 단위로 맞았습니다. 많이 안 맞으면 열 매핑이 틀린 것입니다.)

## 6. 정산 화면 설계 (트러스트맵용)

프리스 대표님과 정한 화면 방식입니다. `ui_prototype/settlement_screen_demo.html` 을 브라우저로 열면 9월 실제 결과(고객 이름·번호는 가림)로 동작하는 예시를 볼 수 있습니다.

- **고객 건별 표**로 쭉 나열한다. 누르기 전에는 **금액만**(판매일보 / 정산서 / 차이) 보인다.
- 색: **일치 = 초록**, 정산서가 더 줌 = 파랑, 정산서가 덜 줌 = 빨강. 덜 받은 건이 맨 위.
- **고객을 누르면** 펼쳐서 보여준다:
  1. 결과 한 줄 — "정산서가 10,000원 덜 줬어요"
  2. **예상 원인** — 예: "정산서에서 'U+ONE 미로그인 차감' −10,000원 — 판매일보 메모에는 없는 차감 → 개통 조건 확인" (`causes`)
  3. **점검 (큰 틀)** — 정책 단가(리베이트) / 부가서비스 유치 / 개통 조건 / 정책 추가금 각각 ✓ 정상, ! 차감 있음, ✕ 차이 원인 (`checks`)
  4. **항목별 대조** — 판매일보 메모 줄과 정산서 항목을 짝지어 "맞음 / 정산서에만 / 판매일보에만" 표시 (`memo_match`)
  5. 판매일보 메모 원문, 차액 계산에서 뺀 항목(참고)
- 위쪽 요약 카드: 총액 차이, 일치·더 받음·덜 받음 건수와 금액. 카드를 누르면 그 상태만 걸러 보기.
- 아래쪽: 판매일보에만 있는 건(추정 사유 포함), 정산서에만 있는 줄·매장 단위 항목.

예상 원인은 판매일보 **메모(AE열)** 를 활용합니다. 판매자가 "보험 미가입 -1", "유통망15이상 +3" 처럼 만원 단위로 적어 둔 줄을 정산서 항목과 금액으로 짝지어서, 짝이 안 맞는 줄을 원인으로 보여줍니다(9월 경기 161건 중 142건 대조 가능). 메모 합계가 구두−차감금액과 다르면 정산서 항목 조합으로 추정하고 "추정"으로 표시합니다.

## 7. 트러스트맵(트러스트플로우)에 넣을 때

권장 구조: **이 `settlement/` 엔진은 고치지 말고 그대로 두고**, 트러스트맵에는 화면과 API만 붙입니다.

- 트러스트맵 백엔드가 Python(FastAPI·Django 등)이면: `from settlement.engine import reconcile` 로 바로 호출
- 다른 언어(Node.js 등)면: 이 엔진을 작은 Python API 서비스로 따로 띄우고(예: FastAPI `POST /settlement/reconcile`) 트러스트맵이 호출

API 예시 (제안):

```
POST /settlement/reconcile   (multipart/form-data)
  year, month
  sales_본점, sales_2호점, sales_3호점   (판매일보 파일)
  vendor_code                           (gyeonggi | juan | naeway)
  vendor_files[]                        (정산서 파일 1개 이상)
→ 200 { summary, items, unmatched_vendor, unmatched_sales, excel_url }
```

화면 제안: 업로드 → 결과 요약 카드(일치/초과/부족 건수, 총액 차이) → 색상 표(상태 필터, 매장·판매자 필터) → 엑셀 다운로드.

**개인정보 주의**: 판매일보·정산서에는 고객 이름과 전화번호가 들어 있습니다. 로그인한 매장 관리자만 볼 수 있게 하고,
업로드 파일과 결과의 보관 기간을 정해 두세요. 고객 정보를 외부 AI 서비스에 그대로 보내지 않는 것이 안전합니다.

### ChatGPT 등에 맡길 때 같이 붙여넣을 지시문

> 첨부한 `settlement_program` 폴더는 휴대폰 매장의 판매일보와 거래처 정산서를 대사하는 Python 엔진이다.
> 1) `settlement/` 폴더의 계산·매칭 로직과 `RULES.md`(정산 규칙 명세) 의 규칙은 **바꾸지 말고 그대로** 사용해라. 특히 유통망지원금·현금판매분·추가지원금·유심비·이동통신료를 차액 계산에서 빼는 규칙, 거래처별 부호 처리, 2단계 매칭은 의도된 것이다.
> 2) 트러스트맵에는 파일 업로드 화면, 결과 표 화면(빨강=부족, 초록=초과, 노랑=일치), 엑셀 다운로드, 그리고 엔진을 호출하는 API만 추가해라. 엔진 호출은 `reconcile(vendor_code, year, month, sales_files, vendor_files)` 하나다.
> 3) 다 붙이고 나면 2026년 9월 파일로 실행해서 결과 숫자가 아래와 같은지 확인해라:
>    경기서부모바일 매칭 161건(일치 130 / 초과 20 / 부족 11), 총액 차이 +440,000원 /
>    KT 주안정보통신 매칭 10건(일치 6 / 초과 1 / 부족 3), 총액 차이 +60,000원.
> 4) 고객 이름·전화번호가 있으므로 로그인·권한 체크를 반드시 넣어라.
> 5) 결과 화면은 `ui_prototype/settlement_screen_demo.html` 과 같은 방식으로 만들어라: 목록에는 금액만(판매일보/정산서/차이), 고객을 누르면 결과 문장·예상 원인(`causes`)·점검표(`checks`)·항목별 대조(`memo_match`)·판매일보 메모를 펼쳐 보여준다. 색은 일치 초록, 더 받음 파랑, 덜 받음 빨강.
