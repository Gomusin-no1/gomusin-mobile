# 정산 대사 규칙 명세

이 문서는 프로그램이 따르는 업무 규칙입니다. 2026년 8~9월 실제 데이터를 놓고 매장 대표가 직접 확인·지시한 내용이며,
코드를 옮기거나 다시 짤 때도 **이 규칙은 그대로 유지**해야 합니다.

---

## 1. 판매일보 (매장 자체 기록)

- 매장별 엑셀 1개(본점·2호점·3호점), 월별 시트(`09월` 또는 `9월`), 3행 헤더, 4행부터 데이터.
- A열 날짜는 같은 날 두 번째 줄부터 비어 있음 → 위 행 날짜를 이어 씀.
- 한 고객이 휴대폰 + 인터넷/TV 결합처럼 여러 상품을 개통하면 상품마다 줄이 따로 있음.
  기종(D)에 `인터넷`·`TV`·`티비`·`동판`·`중고가입`이 있으면 결합(유선) 줄로 본다.
- 성명(B) 칸에 메모가 줄바꿈으로 붙거나(`이윤정\n숭의점접수`), 영문 이름이 두 줄로 나뉘는 경우가 있음.

## 2. 공통 비교 원칙

**판매일보_비교금액 = P(리베이트) + Q(구두) − R(차감금액)**

다음은 차액 계산에서 **완전히 제외**한다 (리베이트에도 더하지 않는다):

- 판매일보 S·T열(할부프리/추가지원금, 유통망지원금/현금개통), U 유심비, V 이동통신료
- 정산서 쪽의 같은 성격 항목: 유통망지원금, 현금판매분, 추가지원금, 현금판매 기기대금, 유심(후청구), 이동수수료/번동료

> 배경: 처음에는 정산(W) 전체를 비교했는데, 유통망지원금이 리베이트보다 큰 결합 건에서 수백만 원짜리 가짜 오차가 생겼다.
> 매장마다 S·T열 의미가 달라서(현금개통은 고객이 낸 돈) 지원금끼리 짝을 맞추는 방식도 틀렸다.
> 그래서 사용자 지시로 "유통망지원금 및 현금판매건은 정산차액에서 빼고", "이동통신료 800원·유심비 7,700원도 제외"하기로 확정했다.
> 이 규칙으로 바꾼 뒤 8월 경기 최대 오차가 수백만 원 → 8만 원으로 줄었다.

결과 상태:

- `diff = 정산서_비교금액 − 판매일보_비교금액`
- 0 → **일치(노랑)**, 양수 → **초과(초록, 정산서가 더 줌)**, 음수 → **부족(빨강, 확인 필요)**
- 정렬: 부족 → 초과 → 일치

차이 설명을 위해 두 부분으로 나눠 보여준다:

- ① 리베이트: 판매일보 P ↔ 정산서 리베이트 열 (거래처별 열 이름은 아래)
- ② 기타조정: 판매일보 Q−R ↔ 정산서 비교금액 − 정산서 리베이트

지금까지 3개 거래처 모두 ① 리베이트는 거의 전부 원 단위로 일치했다. 리베이트가 대량으로 안 맞으면 열 매핑을 의심할 것.

## 3. 매칭 규칙

1. 판매일보에서 **청약점(F)에 거래처 키워드가 들어간 줄**만 대상 (경기 / 주안 / 내외).
2. **1차(엄격) 매칭**: 정산서 줄마다 후보 판매일보 줄을 찾는다.
   - 휴대폰(무선) 줄: 전화번호(마스킹 허용) 일치 + 고객명 마스킹 패턴 일치 + 날짜 차이 45일 이내.
     후보가 여럿이면 ① 결합 줄이 아닌 것 ② 기종이 비슷한 것(폰+워치를 같은 이름·번호로 개통한 경우 구분) ③ 날짜가 가까운 것 순.
   - TV/인터넷(유선) 줄: 정산서에 전화번호가 없으므로 판매일보 결합 줄 중에서 고객명 패턴 + 가까운 날짜.
3. **2차(보정) 매칭**: 1차에서 남은 것끼리만, 날짜 ±1일 안에서
   - 번호 끝자리가 같고 이름 첫 글자가 같으면 매칭 (이름 표기 차이, 예: 정산서 `J***********G` ↔ 판매일보 `JIN MINGSHEN`)
   - 이름 패턴이 같으면 매칭 (번호 누락·오타, 예: 정산서 3470 ↔ 판매일보 3740)
   - 2차 매칭 건은 결과에 사유를 표시해서 사람이 확인하게 한다.
4. 배정은 1:1. 후보가 적은 정산서 줄부터 먼저 배정해서 충돌을 줄인다.
5. **매장 구분은 항상 판매일보 기준.** 정산서의 판매처/계정 표기는 실제 매장과 다를 수 있다
   (주안 3호점 계정에 본점 판매가 섞여 있었고, 내외 정산서의 "3호점" 표기 건이 실제로는 본점 판매였다).

마스킹 처리:

- 이름: 연속된 `*` 는 "0글자 이상 아무 글자". 한글은 `오*식`, 영문은 길이와 상관없이 `Q********I`, `LI* *********NG` 처럼 가림.
- 번호: `*` 는 숫자 1자리. `010-****-3654`(경기), `010-56**-*924` / `01053***425`(주안), 전체 노출(내외).

## 4. 거래처별 규칙

### 4-1. 경기서부모바일 (청약점 `경기`)

- 시트 1개, 7행 헤더(`가입번호`…), 8행부터 데이터. 상단에 정산금/공과금/실지급 요약.
- **부호**: 금액이 음수 = 매장에 지급. 비교·표시할 때 부호를 바꿔 매장 기준(+받음)으로 쓴다.
- 줄 종류: 무선 / TV결합(유형2에 `DPS`) / 퀵비(가입번호 `퀵비`) / 해지반환.
- 정산서_비교금액 = −지급계 = −(액면 + 액면과 지급계 사이의 모든 열: 별도추가1·2, 기타추가, 축소정책, 유통망10만미만·U+ONE 차감, 부가서비스 VAS·보험류·SET추가, `-` 열 등)
- 리베이트 = −액면
- 제외: 유통망지원금, 현금판매분 (실지급계 = 지급계 + 유통망지원금 + 현금판매분), 번이수수료
- 퀵비·해지반환은 매장단위 항목 → 미매칭 시트로.

### 4-2. KT ㈜주안정보통신 (청약점 `주안`)

- 계정(매장 코드)마다 .xls 1개. 시트: 통계 / 무선 / 유선 / 기타 / 유심 인수단말 / 수정요청.
- **월마다 열 위치가 바뀐다** (2026-09: 리베이트 W→Y, `추가지원금 판매수수료 초과건` 열 신설, 상세 정책 항목 증가). 반드시 항목명으로 열을 찾을 것.
- 무선 시트: 2행 그룹(①판매수수료 / ②현금판매 기기대금 / ③세금계산서 미발행 / 실지급액 / 무선 수수료 상세), 3행 항목명.
  - 무선 수수료 = 리베이트 + 무선 수수료 상세 항목(추가정책, 필수팩, 보험, 스팟, 별도추가 …)의 합
  - ① 합계 = 무선 수수료 + 추가지원금 + 유심후청구 (예외: 할부원금 0 인 완납형 고액지원 건은 추가지원금이 ② 쪽으로 옮겨짐)
  - 실지급액 = ① 합계 + ② 합계 + ③ 합계
- 정산서_비교금액(무선) = **무선 수수료**, 리베이트 = `리베이트` 열
- 제외: 추가지원금, 유심후청구, ② 합계(현금판매 기기대금), ③ 항목(추가지원금 판매수수료 초과건, 번동료·보증보험수수료·특별수납)
- 유선 시트: 정산서_비교금액 = 총 유선 수수료 (리베이트 분리 없음, 종합 금액만 비교)
- 기타(퀵비·전자계약비 등)·유심 인수단말(유심 구매)은 매장단위 항목 → 미매칭 시트에 합계로.
- 개통구분 `유심`(유심 단독)은 수수료 0, 유심후청구만 있는 줄.
- 통계 시트: 실수령 = ①판매수수료 합계 + ②단말기·유심대금 합계 + ③미발행 합계.

### 4-3. 내외정보통신 (청약점 `내외`)

- 시트 1개, 4행 헤더(`순 번`, `모 델 명` …), 5행부터 데이터, 아래에 합계 줄과 안내문.
- 여러 통신사(LGT/SKT …) 건을 함께 취급. 개통번호 전체 노출.
- 일련번호가 없는 줄(예: `5월 부가서비스 미유지 환수`)은 매장단위 조정 건.
- **부호가 반대**: 총정산금 = 모든 항목의 단순 합이고 대부분 음수 = 매장이 낼 돈. 비교할 때 부호를 뒤집는다.
- 정산서_비교금액 = −(필수팩 + 보험 + 요금제추가 + KT정책추가(실제 의미: 추가지원금 활성화) + 요금할인추가 + 별도정책추가 + 제휴카드추가 + 차감 + 선납금 + 리베이트)
- 리베이트 = −리베이트 열
- 제외: 추가지원금(판매일보 T열과 같은 값), 유심, 이동수수료, 현금건

## 5. 미매칭 처리

- 정산서에만 있는 줄: 미매칭 시트. 매장단위 항목(퀵비, 유심 구매, 환수, 해지반환)은 "1:1 매칭 대상 아님"으로 따로 표시.
- 판매일보에만 있는 줄: 추정 사유를 붙인다.
  - 결합(유선) 줄
  - 월말 3일 이내 개통 → 다음 달 정산서 반영 가능성
  - (주안) 받은 계정 정산서에 없음 → 아직 안 받은 다른 계정 정산서에 있을 수 있음
  - 그 외 → 누락 여부 확인 필요

## 6. 예상 원인 분석 (2026-10 추가)

화면에서 고객을 누르면 "무엇이 틀렸고, 맞는 건 무엇이고, 무엇 때문으로 예상되는지"를 보여준다.

1. **판매일보 메모(AE열 '구두내용/부가추가/차감내역') 대조** — 우선 적용
   - 줄마다 끝의 `+숫자` / `-숫자` 를 **만원 단위**로 읽는다 (`보험 미가입 -1` = −10,000, `상품권 + 10` = +100,000).
   - 메모 금액 합계가 판매일보 **구두(Q) − 차감금액(R)** 과 정확히 같을 때만 쓴다.
     (같지 않으면 '중고폰·페이백·사은품·현금·퀵' 이 들어간 줄을 빼고 한 번 더 확인)
   - 정산서 상세 항목과 짝짓는 순서: ① 같은 금액 + 이름 비슷(보험↔보험류, 교보·V컬↔VAS …) ② 메모 2줄 = 정산서 1항목
     ③ 같은 금액 ④ 메모 2줄 = 정산서 1항목(이름 무관) ⑤ 정산서 2항목 = 메모 1줄
   - 짝이 안 맞고 남은 줄이 원인. `상품권 +3 / 상품권 −3` 처럼 서로 상쇄되는 줄은 원인에서 뺀다.
   - 남은 판매일보 메모 줄의 금액이 리베이트 차이와 같으면(예: 메모 `105유치-6`, 리베이트 −60,000)
     "판매일보는 차감금액으로, 정산서는 리베이트에서 깎아서 반영한 같은 내용"으로 보고 실제 차이에서 뺀다.
2. 메모 대조를 못 하면 **정산서 항목 조합**으로 추정: 차이 금액과 합이 정확히 같은 항목 1~3개 조합을 찾는다
   (같은 부호 항목 우선). 조합이 여러 개면 "추정"으로 표시.
3. 리베이트 차이는 따로 "정책 단가(리베이트)" 원인으로 표시 → 개통 시점 단가표(모델·요금제·개통유형) 확인.

**점검표(큰 틀)**: 정산서 상세 항목을 이름으로 분류한다.

| 분류 | 항목 이름에 들어가는 말 |
| --- | --- |
| 부가서비스 | 부가, VAS, 보험, 필수팩, OTT, SET, 케어, 구독, 미유치, 원스톱, 인터넷팩 |
| 개통 조건 | 유통망지원금10(만 미만), U+ONE, 로그인, 축소(선약·33미만·기변 차감), 요금제, 요금할인, 제휴카드, 선납, 모든G, 미만 |
| 정책 추가금 | 별도, 기타추가, 추가정책, 스팟, 소급, 활성화, KT정책, MIT |
